# CONSTITUTION.md - Real-Time Loudness & Tonal Balance Meter

## 1. Core Principles & Philosophy
- **Accuracy First**: Measurements must strictly adhere to industry standard DSP formulas (ITU-R BS.1770-4 for LUFS/True Peak). Zero tolerance for visual inaccuracies or arbitrary metering smoothing.
- **Real-Time Priority**: The application is built for real-time monitoring (Broadcast & Mastering). The audio processing thread must remain pristine, deterministic, and glitch-free under all user interactions.
- **Cross-Platform Parity**: Identical DSP behavior, audio rendering, feature set, and preset capabilities across macOS (Apple Silicon native) and Windows (x64).
- **Always Work under Sofware Spec Development framework**: Create, edit and mantain all documentation aligned with the latest standards according SDD framwork.
-  **Always chat in spanish and write documentation and code in english**

---

## 2. Hard Architectural Rules (Non-Negotiable)

### 2.1 Audio Thread Hygiene
- **Zero Allocations**: NO dynamic memory allocations (`malloc`, `new`, `std::vector::resize`, `juce::String` concatenation) inside the audio process loop (`processBlock`).
- **Zero Lockings**: NO mutexes, locks, critical sections, or thread synchronizations inside `processBlock`.
- **Zero Disk/Network I/O**: NO file reading, JSON parsing, logging, or web request triggers on the audio thread.
- **Communication Pattern**: All communication between `AudioProcessor` (Audio Thread) and `AudioProcessorEditor` (UI Thread) MUST use lock-free Single-Producer Single-Consumer (SPSC) ring buffers or `std::atomic` variables.

### 2.2 Framework & Build System Constraints
- **Framework**: JUCE 7+ using C++20 standard constructs.
- **Build System**: Single source of truth using CMake (`CMakeLists.txt`). No platform-dependent project files (`.xcodeproj`, `.sln`) allowed in version control.
- **Target Formats**: Standalone Executable, VST3 Plugin, and Audio Unit (AU) for macOS.

---

## 3. UI/UX Rules
- **60 FPS Performance**: UI updates must run via lock-free polling timers capped at 60 FPS. If CPU usage on the GUI thread spikes above 5%, rendering detail must dynamically scale back.
- **High-DPI / Resizable UI**: Layouts must use flex/grid scalable coordinates. UI elements must scale crisply on Retina and 4K displays without blurring.
- **Target Visual Feedback**: Visual cues (colors/highlights) must react immediately when metrics enter/exit target preset thresholds.

---

## 4. Licensing & Distribution Abstraction
- Core DSP logic and GUI elements must NEVER be tightly coupled with licensing logic.
- All copy protection, CDKey validation, or activation checks must reside behind a pure abstract interface (`ILicenseValidator`).
- In MVP phase, `DummyLicenseValidator` (always returns `true`) will be injected via Dependency Injection.

---

## 5. Definition of Done (DoD) for Any Increment
A feature or code modification is considered DONE only if:
1. It compiles without warnings on both Apple Silicon (macOS) and MSVC (Windows x64).
2. It does not introduce audio dropouts, memory leaks, or dynamic allocations on the process block.
3. It passes all DSP calibration unit tests (sine wave at -12 dBFS = -12 LUFS / True Peak check).
4. The `.dmg` and `.exe` CI/CD build actions complete successfully.
